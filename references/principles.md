# The ten principles

The commitments this suite is built on. Each skill opens `## Purpose` with the ones it rests on:
`**Stage: <stage>.** Principles <numbers>.`

1. **Ownership is three-way.** The person owns intent, constraints and acceptance. The agent owns
   context, decomposition, execution and evidence. Gates own the verdict.

2. **Harness complexity tracks model capability.** A mechanism is written beside the model assumption
   justifying it, and goes when that assumption dies.

3. **Context is a budget.** At most 40 instructions per skill, about 200 in play at once, a cap on every
   artifact. A sentence that changes no behaviour is over budget by definition.

4. **A skill is a workflow with a verifiable end, not an essay.** A directive description, a body that is
   the method and its gotchas, depth in references loaded per task. Practices are kept as invocations,
   never as arguments for why they matter.

5. **Files are split by cold reader, not by writer.** One reason to exist, one reader who opens it alone,
   one writer. A shape is stated once, where the file is written.

6. **Inputs help; they never gate.** Read an input if present; derive it and mark it `derived` if absent.
   With a person there, ask at most three questions, only where the gap changes the shape.

7. **Decide and leave a trace.** Default with a reason, proceed, log it, show it where the person
   reviews. Only the stop list ends a slice. Nothing is frozen — what judges the work may change when
   the plan moved, visibly, in the pull request.

8. **Maker ≠ checker through independent evidence.** The checker uses evidence the maker did not: a
   fresh context, the running app, a measurement. Never a persona, never the maker's own context.

9. **What a command can check, a command checks.** What it cannot is stated once and cited.

10. **Attention follows error amplification.** Deepest human attention at intent and design, moderate at
    plan, minimal at implementation.
